# Нотатки з безпеки

Secure Drive використовує клієнтське шифрування вмісту файлів.

## Криптографія

- Симетричний режим: AES-GCM із 256-бітним ключем.
- Отримання симетричного ключа: PBKDF2 із SHA-256 і випадковим salt.
- Асиметричний режим: hybrid RSA-OAEP + AES-GCM.
- RSA-OAEP використовується для захисту AES-ключа, а не для прямого шифрування великих файлів.
- IV: випадкове 96-бітне значення для кожного файлу.
- Серверні метадані цілісності файлу: SHA-256 checksum від ciphertext.

## Межа довіри

Backend ніколи не отримує пароль шифрування файлу або plaintext-байти файлу. Він зберігає лише ciphertext і метадані.

Паролі облікових записів надсилаються на backend для входу й зберігаються як password hashes. Паролі шифрування файлів є окремими й залишаються в браузері.

Private key користувача зберігається тільки в зашифрованому вигляді. У браузері він розблоковується паролем акаунта після входу.

## Обмеження застосунку

- Паролі облікових записів мають містити 8-128 символів, велику латинську літеру, малу латинську літеру та символ.
- Завантажувані файли обмежені розміром 50 MB.
- Завантаження `.exe` і `.mp4` блокується за розширенням оригінальної назви файлу.
- Скидання пароля реалізоване через локальний development email-log у `backend/mail/reset_emails.log`.
- Для shared-файлів frontend рахує невдалі спроби розшифрування. Після третьої помилки backend записує IP і дані запиту в `backend/security_logs/attackers.log`.

## Вимоги до експлуатації

- Замінити `SECRET_KEY` перед production-використанням.
- Обслуговувати frontend і backend через HTTPS.
- Для локального HTTPS використовується self-signed сертифікат `infra/certs/localhost.pem` і приватний ключ `infra/certs/localhost-key.pem`.
- У Docker-режимі TLS завершується на nginx, а запити до backend передаються всередині docker network.
- Використовувати сильні паролі й передавати паролі шифрування файлів окремим каналом.
- Додати rate limiting і audit logging перед публічним розгортанням.
